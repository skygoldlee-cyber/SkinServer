## A. 관측성 심화 — 지금은 "살아있나"만 보고 "어떻게 쓰이나"는 못 봄

| 항목 | 현재 상태 | 보완 내용 |
|---|---|---|
| 기본 메트릭 | 공백 | 요청률·지연·큐 길이·GPU VRAM 수집(지금은 `remote-status.sh`가 순간 스냅샷만 제공) |
| 에러 집계 | 없음 | Sentry 등으로 예외를 그룹화·알림 |
| 알림 배선 확인 | 부분 | `alert.sh`는 있으나 cron 5분 등록 + `deploy.sh` 롤백 훅 연결이 실서버에서 확인돼야 함 |

> 원격 레이어와의 관계: `remote.ps1 status`는 **지금 당장의 수동 점검**용이고, 이 항목들은 **시계열 수집·자동 알림**이라 상호보완이다.

## B. 테스트·품질 게이트 — 현재 배포는 헬스체크만 통과하면 올라감

| 항목 | 현재 상태 | 보완 내용 |
|---|---|---|
| 빌드 전 게이트 | 없음 | 단위/통합 테스트·린트 + 이미지 취약점 스캔(trivy) + `compose config` 검증 |
| 배포 후 스모크 | 없음 | 실제 분석 1건을 돌리는 e2e 스모크 |
| 마이그레이션 리허설 | 없음 | 스테이징에서 upgrade/downgrade 리허설 |
| **P1-3 presigned E2E·RLS 검증** | 🔴 **미해결** | `tests/integration/`에 presigned 플로우·RLS SQL 검증 없음(현재 multipart 경로만). Phase 4 완료 조건 |

## C. DR·용량 — 백업은 있으나 복구·한계는 미측정

| 항목 | 현재 상태 | 보완 내용 |
|---|---|---|
| 복구 리허설 실행 | 파일만 있음 | `restore-rehearsal.sh`를 스테이징에서 1회 실행해 RPO/RTO를 `restore-rehearsal.md` 표에 실제 기록 |
| 용량 한계 | 미정 | 단일 GPU 병목의 큐 적체 정책(대기/거절) 확정 |
| 부하 테스트 | 없음 | k6/locust로 처리량·한계 측정 |

## D. 개인정보·보안 — 파일은 있으나 운영 반영·문서 미완

| 항목 | 현재 상태 | 보완 내용 |
|---|---|---|
| htpasswd bcrypt 재발급 | 미완 | bcrypt 재발급 + 커밋 제외 + dev IP 화이트리스트 |
| 개인정보 처리 흐름 문서 | 없음 | 수집·보관·파기·국외이전(Supabase 리전) 고지, 삭제 요청 시 원본+파생+로그까지 지우는 절차 |
| RLS 차단 테스트 | 미완 | 다른 유저로 접근이 실제로 차단되는지 검증 |

## 권장 우선순위

1. **D4 실제 믹스표** — prod fail-fast 배포 블로커라 병행 착수 필수.
2. **P1-3 presigned E2E·RLS 검증** — Phase 4 완료 조건이자 보안 보장을 코드로 고정.
3. **복구 리허설 1회 실행** — 스테이징에서 돌려 RPO/RTO 확정("백업은 있는데 복구는 안 핵" 함정 닫기).
4. **관측성 심화(메트릭·Sentry)** — 사고를 "보이게". 원격 레이어와 상호보완.
5. 이후 B(테스트 게이트) · D(개인정보 문서) · F(문서) 순.
