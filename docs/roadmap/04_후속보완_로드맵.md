# 후속 보완 로드맵

P0×4 + P1(flock)까지 반영된 상태에서, **실사용·운영에서 실제로 필요한데 아직 비어 있는 것**을
주제별로 정리한다. 가장 먼저 손댈 3개(①~③)는 `deploy/ops-jobs/`에 실제 파일로 반영했다.

## 우선 3개 — 파일로 반영됨

| # | 항목 | 반영 파일 |
|---|---|---|
| ① | 이미지/PII 보존·삭제 잡 + 로그 스크러빙 | `deploy/ops-jobs/retention.py`, `log-scrub.py`, `nginx-log-privacy.conf` |
| ② | 최소 관측성(구조적 로깅 + 알림) | `deploy/ops-jobs/observability/logging_config.py`, `alert.sh`, `crontab.example` |
| ③ | 백업 복구 리허설 | `deploy/ops-jobs/restore-rehearsal.sh`, `restore-rehearsal.md` |

배선·설정 방법은 `deploy/ops-jobs/README.md` 참고.

> 이 문서는 **전체 백로그**(7개 주제)다. **미완 항목만 추려 계약 경계로 정리한 것**은 [`05_보완항목_정리.md`](./05_보완항목_정리.md)를 본다.

## 주제별 백로그

### 1. 개인정보·보안 운영편 (P1)
- 보존을 문장이 아니라 **잡으로**: presigned TTL(5~10분), 리포트 생성 후 원본 자동 삭제,
  미완료 업로드 정리. → `retention.py`(①)
- **로그 스크러빙**: 앱·nginx 로그에 이미지 URL·토큰·PII 미기록. → `log-scrub.py`·`nginx-log-privacy.conf`(①)
- `.htpasswd` bcrypt 재발급 + 커밋 제외 + dev IP 화이트리스트.
- **개인정보 처리 흐름 문서**: 수집·보관·파기·국외이전(Supabase 리전) 고지, 삭제 요청 시
  원본+파생+로그까지 지우는 절차.

### 2. 관측성 (현재 사실상 공백)
- 구조적 JSON 로깅 + `job_id` 상관ID로 한 요청을 끝까지 추적. → `logging_config.py`(②)
- 기본 메트릭: 요청률·지연·큐 길이·GPU VRAM. 에러 집계(Sentry 등).
- 알림 채널: 배포 실패·헬스 실패·큐 적체·디스크/VRAM 임계. → `alert.sh`(②)

### 3. 백업·복구·용량 (DR)
- **복구 리허설**과 RPO/RTO 목표 확정("백업은 있는데 복구는 안 해봄" 함정 닫기). → `restore-rehearsal.*`(③)
- 단일 GPU 병목의 **용량 한계·대기열 정책**(적체 시 대기/거절) + 부하 테스트(k6/locust).

### 4. 테스트·품질 게이트 (현재 배포는 헬스체크만)
- 빌드 전 단위/통합 테스트·린트, 이미지 취약점 스캔(trivy), `compose config` 검증. (테스트 실행 가이드: [서버 실행·운영 가이드 - 8. 자동화 테스트 실행 가이드](../operations/서버_실행_운영_가이드.md#8-자동화-테스트-실행-가이드) 참조)
- 배포 후 e2e 스모크(실제 분석 1건), 스테이징에서 마이그레이션 upgrade/downgrade 리허설.

### 5. 문서 보완
- **환경변수 레퍼런스** 표(`.env` 전 항목: 용도·필수·기본값·비밀 여부).
- **API 계약(OpenAPI)** + job 상태 스키마·에러 코드, **데이터 모델/ERD** + Storage 키 규약(`{user_id}/{job_id}/…`).
- **인시던트 런북**(증상→진단→조치)과 **ADR**(왜 Supabase·왜 폐쇄망·왜 self-hosted 러너).
- **피부분석 및 처방전 엔진 고도화 계획**: OpenCV/Heuristics 기반 스텁에서 딥러닝 추론(RetinaFace/MediaPipe/CodeFormer) 및 다차원 안전 처방 엔진으로 전환하기 위한 Seam 설계 및 액션 플랜 수립. (참조: [`engine_advancement_roadmap.md`](./engine_advancement_roadmap.md))
- `services/`·`apps/`(옛 스캐폴드 코드)와 `deploy/`(배포 스택)의 역할 경계를 상위 문서(`../README.md`·`../MANIFEST.md`)에서 재확인(compose는 `deploy/compose/`로 단일화되어 중복 nginx/compose 혼동은 해소됨).

### 6. 남은 결정/마무리 (P0에서 넘어온 것)
- GPU: 실제 호스트 `nvidia-smi` 검증 + `WORKER_CONCURRENCY` 튜닝 결과 기록.
- TLS: 도메인/이메일 실제값·DNS·Caddy 발급 확인.
- RLS: 실제 테이블/컬럼명 확정 후 적용 + **다른 유저로 접근 차단 테스트**.
- gateway를 enginenet에서 제외할지 결정(P2).

### 7. 오버뷰 페이지(선택)
- GitHub Pages에선 카드의 `.md` 링크가 렌더 안 될 수 있으니 md→html 변환 또는 저장소 뷰 URL로 전환.
- 마지막 업데이트 날짜·OG 태그(공유 썸네일) 추가.

## 권장 순서

1. ①(개인정보) — 민감정보라 가장 시급. 보존 잡 + 로그 스크러빙 배선.
2. ②(관측성) — 구조적 로깅 + 알림. 사고를 "보이게".
3. ③(복구 리허설) — 스테이징에서 1회 돌려 RPO/RTO 확정.
4. 이후 4·5(테스트 게이트·문서)로 확장.
