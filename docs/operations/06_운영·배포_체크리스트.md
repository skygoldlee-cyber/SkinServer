## 0. 조용히 터지는 것 — 제일 먼저 확인

명령은 맞는데 WSL/Docker 특성 때문에 **에러 없이 새는** 항목이라 최우선입니다.

- [ ] **ufw로 Docker 발행 포트가 안 막힘을 인지** — `ufw deny 5432`가 걸려 있어도 `-p`로 발행한 포트는 외부에 열림. — 근거: v2 §1, 가이드 20-2, 런북 §7-1
- [ ] compose에서 db·redis(Phase 3 예정)·gateway·엔진은 **`127.0.0.1:` 바인딩**(또는 클라우드 보안그룹), 공개는 nginx만. — 근거: v2 §2, 가이드 9-3-1
- [ ] **다른 망에서 `nc -vz <서버> 5432/8080/3001` 로 실제 차단을 검증**(또는 로컬 `verify_client.ps1 -Check ports`). 서버측 하드닝 적용값은 `./verify_server.sh hardening`. — 근거: v2 §1, 런북 §7-1, 가이드 §12 hardening 모듈
- [ ] 관리 콘솔(adminer·uptime-kuma·db)은 **SSH 터널로만** 접근(`ssh -L 8080:localhost:8080 …`). — 근거: 런북 §7-1, 가이드 9-3-1
- [ ] **WSL idle 종료로 새벽 백업이 누락되지 않게** 시간기반 작업을 Windows 작업 스케줄러가 WSL을 깨워 실행(`wsl-backup-task.ps1`). native/VPS(systemd)는 해당 없음. — 근거: v2 §3, 가이드 18-2-1

## A. 배포(CD)

- [ ] **하이브리드 빌드 분리 유지** — 정적=rsync(빌드·게이트 없음) / gateway·worker=서버 빌드+sha 태그 / 엔진=CI→GHCR→서버 pull. — 근거: CD 큰 그림, 이야기 배포편
- [ ] **러너는 pull(아웃바운드 폴링)·서비스 상시** — 인바운드 개방·웹훅 불필요, WSL idle도 해소. — 근거: CD 큰 그림·§1
- [ ] 멀티레포면 **러너를 GitHub 조직 레벨 2대**로(개인계정은 레포마다 붙여야 함). — 근거: CD §1
- [ ] **운영 배포 승인 게이트** — Environments `production` 에 Required reviewers 지정(스테이징은 자동). — 근거: CD §4
- [ ] **헬스체크 게이트 + 자동 롤백** 동작 확인 — `deploy.sh` 가 `healthy` 대기, 실패 시 `.env.images` 이전 태그로 즉시 롤백. — 근거: CD 안전장치
- [ ] **동시성 잠금**(`concurrency:`)으로 겹친 배포가 compose 동시 접근 방지. — 근거: CD 안전장치
- [ ] **비밀 분리** — `.env` 는 서버에만·커밋 금지, 러너/CI는 `.env.images` 태그만 갱신. — 근거: CD 안전장치, 가이드 9-2
- [ ] **환경 정렬** — 스테이징 `--profile staging`(임시 냉장고=로컬 db) / 운영 프로파일 없음(db 미기동 + Supabase). — 근거: CD §2, 적합성 §6
- [ ] `dev.conf` Basic Auth 자격증명 교체(`.htpasswd`). — 근거: CD §2
- [ ] GHCR pull 권한 확인(`GITHUB_TOKEN` 또는 public 패키지). — 근거: CD §3
- [ ] DB 스키마 변경 시 마이그레이션 순서 확인. — 근거: CD DB 마이그레이션

## B. 운영

> 아래 항목은 `verify_ops.sh` 로 한 번에 점검할 수 있습니다(가이드 §21 자동화).

- [ ] **GPU·메모리 경합 관리** — 단일 GPU/8GB에 엔진2+웹 동시 = VRAM·메모리 경합 → 실운영은 엔진을 웹과 분리. — 근거: 적합성 §7
- [ ] **업로드·타임아웃** — `client_max_body_size`·프록시 타임아웃은 임시 안전판, 정답은 **비동기 Job Queue**(job_id 즉시 반환, worker가 뒤에서 조리). — 근거: 적합성 §5·부록 C, 이야기 막 0-B
- [ ] **부팅 시 시계 재동기**(`hwclock`) — 절전 후 드리프트 보정. — 근거: v3 §11, 가이드 16-2
- [ ] **자동 업데이트·재부팅 정책** — WSL은 재부팅 끔, VPS는 새벽. — 근거: v3 §10, 가이드 21-1
- [ ] **로그 상한**(journald)·로그 로테이션으로 디스크 넘침 방지. — 근거: v3 §10, 가이드 21-2
- [ ] **가동 감시**(uptime-kuma)로 서비스 상시 여부 확인. — 근거: 이야기 막 3
- [ ] (NAT면) **재부팅 후 portproxy 갱신** — WSL 내부 IP 변동 대응. — 근거: 가이드 16-2, 이야기 구축편 §6

## C. 하드닝 (구축 직후 굳히기)

- [ ] **SSH 변경 락아웃 방지** — `sshd -t` 검증 → 기존 세션 유지한 채 새 창으로 키 접속 확인 → 그제야 비밀번호 잠금. — 근거: v3 §1, 가이드 5-3·5-4·6-4
- [ ] **SSH 하드닝**(`MaxAuthTries` 등) 적용. — 근거: v3 §8, 가이드 5-3
- [ ] **컨테이너 권한 축소** — 비루트 + `no-new-privileges` + `cap_drop`. — 근거: v3 §4, 가이드 9-4
- [ ] **리소스 상한**(mem/cpu) 지정. — 근거: v3 §5, 가이드 부록 compose
- [ ] **엔진 폐쇄망(Case A)** — `enginenet: internal`, 엔진에 Supabase 자격증명 미주입(egress 차단). — 근거: 적합성 §3·부록 B
- [ ] **Docker 데몬 하드닝**(`daemon.json`: 재시작 유지·로그 상한). — 근거: v3 §6, 가이드 8-B
- [ ] **nginx 표면** — `server_tokens off`·보안 헤더·레이트리밋. — 근거: v3 §7, 가이드 9-5
- [ ] **fail2ban 한계 인지** — WSL NAT에선 원본 IP가 게이트웨이로 보여 오차단/무의미 → native·미러에서 원본 IP 보존. — 근거: v2 §6, 가이드 20-1

## D. 백업 (PIPA 필수)

- [ ] **실장부는 Supabase → 백업·PITR은 Supabase가 담당**. 로컬 `pg_backup` 은 스테이징(임시 냉장고)용. — 근거: 적합성 §6, 이야기 막 4
- [ ] **백업 암호화 + 오프사이트 복제 + 보존 하한 + 데드맨 스위치**. — 근거: v3 §3, 가이드 18-1
- [ ] **덤프 성공 시에만 최종 파일 커밋**(0바이트 백업 방지), 계정/DB는 `.env` 에서 읽기. — 근거: v2 §4, 가이드 18-1
- [ ] **위험 공사(커널·데몬) 전 `wsl --export` 스냅샷**. — 근거: v3 §2, 가이드 15-A

## E. 이관 컷오버 (집 → 상가)

- [ ] **DNS TTL 낮춤** → **점검 모드(쓰기 중지)** → **델타 덤프** → **`verify -Mode prod`** → **DNS 전환** → **원본 잠시 유지(롤백)**. — 근거: 런북 §8, 이야기 막 5
- [ ] 쓰기 중지로 **최종 덤프~DNS 전환 사이 쓰기 유실 방지**. — 근거: v3 §9, 런북 §8
- [ ] 이관 전 소스 측 **freeze & 검증**. — 근거: 런북 §3
- [ ] `DATABASE_URL` 특수문자(`@ : / ? # %`)는 `URL.create` 로 조립. — 근거: v2 §5, 가이드 9-2
